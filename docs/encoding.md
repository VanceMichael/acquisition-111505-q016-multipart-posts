# 正文编码子集（yEnc 子集）

来源帖子正文是 yEnc 的受限子集，采集端只按本文件解码，不执行正文内容。

## 报文结构

报文按 CRLF 分行，依次为：

1. `=ybegin part=<n> total=<n> line=<n> size=<总字节数> name=<文件名>`：`name=` 必须是最后一个字段，其值可含空格；`part`/`total` 只是标签，组装不采用。
2. 可选 `=ypart begin=<起点> end=<终点>`：解码字节在整体中的范围，1 起、含端点。缺省时整段即整体，`begin=1`、`end` 为 `=yend` 的 `size`。
3. 编码数据行：编码字节中不会出现 CR/LF，行界不携带数据。
4. `=yend size=<本段字节数> part=<n> pcrc32=<分段CRC> [crc32=<整体CRC>]`。

## 字节变换

- 编码：每个原始字节加 42（模 256）。
- 结果为 0、10、13、61（`=`）时转义为两字节：`=` 后跟该值加 64（模 256）。
- 解码逆向：`=` 引导的下一字节先减 64，所有字节再减 42（均模 256）。

## 校验约定

- `pcrc32`、`crc32` 是 CRC-32（多项式 0xEDB88320，初值与终值异或 0xFFFFFFFF）的 8 位小写十六进制，分别对应解码后的分段字节与完整文件字节。
- 分段必须满足：解码长度等于 `begin..end` 长度且等于 `=yend size`，`pcrc32` 与解码内容一致；不满足的分段不得保管为已验真部分。
- 完整文件必须满足：声明范围无缝覆盖 `1..size`、总长度等于 `size`、整体 `crc32` 与拼装结果一致；缺少 `crc32` 时不得伪造整体验证，只能保管分段。
